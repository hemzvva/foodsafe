## 1. How to work (lessons from the loss)
- **Nothing exists until it is pushed.** The sandbox can be reset after inactivity. Commit and push after every finished file group (at least every stage, better every few files). Also copy each stage zip to `/mnt/user-data/outputs/` and send it with SendUserFile.
- Work inside the repo: kit root = `/home/claude/foodsafe/FoodSafe-Build-Kit/`. The surviving design package stays at `/home/claude/foodsafe/FoodSafe-Project/` and is copied into the kit as `design-package/` at the end.
- No sub-agents. Do the work directly.
- When the harness says the user has not heard from me, send one short SendUserMessage line, then continue.
- Keep the task widget accurate (TaskUpdate as each stage finishes).
- Be honest in every status line: say what is done, what is not, what is unverified.
- No dates, deadlines, day counts or time pressure inside the kit. Provenance "read on <date>" for a verified fact is allowed.
- Never write the owner's e-mail address, finances, country or any personal detail into any file. The support address is the build variable `FS_SUPPORT_EMAIL`. No e-mail-shaped string anywhere except reserved examples (`example.com/.org/.net`, names ending `.invalid`, `.test`, `.example`) and `@2x`/`@3x` image names.
- Python tools: stdlib only, work on Python 3.9+, run with `python3 -I` (the `-I` flag drops the script folder from the import path; tools load siblings by path).
- Memory writes (if any) go only under `/projects/01a1c5af-fa9d-7048-bdea-ce2303411bf0/`.

## 2. The handoff model (keep it simple)
OpenCode will only write code. It gets: the kit zip (decisions, specs, task cards, tools, tests) and one master prompt. Therefore:
- Every decision is already made and written once. A task card says what to build, which docs to read, what tests must pass, and what not to do.
- One precise document per topic. No rule or id is defined twice. Every cited id is defined somewhere (the checker enforces it).
- Anything not verified is marked `confirm` and listed as an open item; the agent must not guess it.
- Ambiguity rule (one rule, everywhere): the agent decides from the documented default, logs the call in `05-PLAN/QUESTIONS.md`, and keeps going. It stops only for things that cannot be undone or cannot be verified from the kit (signing, store submission, spending, a missing owner input).
- Leaner than the lost kit: no duplicated tables, no day-by-day schedules, no padding. Complete for coding; nothing decorative.

## 4. Conventions (re-create exactly; the checker and oracle depend on them)
**Tags in docs:** `[SHOWN: NN:element-id]` or `[SHOWN: «verbatim mockup string»]`; `[DERIVED: reason of at least 15 characters]`; `[NECESSARY: reason]`; `[DECISION D-xx]`; `[REMOVED D-xx]`. Guillemets only around verbatim mockup strings. Ingredient names and examples go in backticks. Never write the literal `[SHOWN: ...]` in running prose.
**Id schemes:** decisions `D-X-nn` (cross-cutting) and `D-NN-k` (per screen); rules `R-NN-k`; business rules `B-01..B-27`; invariants `I-nn`; platform facts `V-nn` (each with source and read-date); open items `U-nn`; acceptance `A-NN-k`; tap budgets `TB-n`; navigation `N-nn`; journeys `J-n`; motion `M-nn`; delight `DM-n`; mockup inconsistencies `MI-nn`; edge states `E-nn`; surfaces `S-01..S-19` (no S-10, S-11); backlog `BL-nn`; content rules `RC-nn`; task cards `T-nn`.
**Checker** (`tools/factcheck_kit.py <file.md>`): errors on undefined decision/acceptance ids, guillemet strings absent from `replica-texts.json`, DERIVED without a 15-character reason, a literal `[SHOWN:` in prose; warnings on the vague words TBD, TODO, probably, maybe, presumably, "and so on", "should be fine", "roughly the same", etc.
**Core API conventions C-1..C-13:** C-1 value types with explicit public init, Sendable and Equatable; C-2 no decimal literals with a point, no `Double` in amount rules (timer seconds are the one Double); C-3 one rounding helper, half up (`NSDecimalRound` with `.plain`); C-4 check the text shape before `parseDecimal` (never call `Decimal(string:)` elsewhere; use locale `en_US_POSIX`); C-5 text built from integers; C-6 time and ids are parameters (no `Date()`, `Calendar.current`, `TimeZone.current`, `Locale.current`, `ProcessInfo`, `UUID()` inside Core); C-7 total orders; names compared by scalar order of `lowercased()`; C-8 no traps; C-9 `/// B-nn` doc comment on each rule function; C-10 pure functions; C-11 one error type `ContentError`; C-12 internal by default; C-13 text builders in Core are literals by design.
**Layering:** `FoodSafeCore <- Data <- Services <- Features <- App`. Core sources in `Types, Content, Rules, Support, Field`.
**Platform facts to re-verify with sources before use (mark `confirm` otherwise):** AlarmKit availability and permission flow; XcodeGen target-source `type: folder` for a resource folder; `NSDecimalRound`; `Decimal(string:locale:)`; `TimeZone.secondsFromGMT(for:)`; Swift String/Unicode scalar ordering; Xcode and SDK requirement for the iOS 26.1 target on the macOS runner; App Store Connect API upload from CI; privacy manifest and nutrition-style privacy label answers.

## 7. Stage 1 designs (these were done once and must be redone the same way)
**Oracle rule semantics.**
- B-08 per line: available -> `have`; else optional line -> `missingOptional`; else the first available member of the line's swap cluster (authored order, skip itself, skip a member with no factor) -> `swap:<id>`; else `missing`. Tier is computed over required lines only (optional never changes the tier, D-X-69). Order of tiers: readyNow, almostReady, smartSwap, none. `[confirm the exact tier thresholds against the rebuilt BUSINESS-RULES]`: readyNow = every required line have; smartSwap = every required line have or swap with at least one swap; almostReady = exactly one required line missing; otherwise none.
- Availability: only rows with days-left >= 0 count; a row in another unit kind than the line makes the line present (presence, not amount); a custom (non-catalog) row never matches an ingredient; amounts in one kind are summed after conversion.
- B-09 key: (tier order, fewer-is-better means more rescued first, i.e. `-rescueCount`, missing count where missing = required missing + missing optional, minutes, lower-case title, id). Rescued ingredients = distinct ingredients behind `have`/`swap` lines that have a row with days-left 0..2 (expired rows do not count).
- B-16 cook-and-deduct: proposals use the amount shown on the screen (scaled amount rounded as displayed), apply in sequence to rows ordered by (expiry, addedAt, id); the event quantity is the row quantity before the take; a row that reaches zero is removed; `startingQuantity` never changes; presence proposals pick the row that expires first. S-16 stock line: for an amount proposal `You have ` plus the B-05 text of the stock in the line's unit (1 L of oil against a ml line reads `You have 1000 ml`); for a presence proposal the B-27 `youHave` text over rows with days-left >= 0.
- B-17 daily digest: 14 requests (days 0..13); a row appears on a day when its days-left on that day is 0..2; equal minute counts count as passed; names distinct case-insensitively.
- B-18 tally by the calendar month AND year of `now`; `used` with days-left-at-event >= 0 counts as used in time; thrown away counts as thrown away.
- B-21 `alertCount` is uncut; `alertRows` at most 3; cook-next line `Uses your a, b and N more` where N = names minus 2.
- B-22 timers: label rounds remaining seconds up; `Time's up` with an ASCII apostrophe; an hour is written `1:00:00 left`; a session is discarded when last touched more than 6 hours ago and no timer has `endsAt > now`.
- B-24 stepper: down is disabled when the result is below the smallest step of the unit (0.15 L and 0.7 pcs have no down).
- B-27 catalog search: query trimmed of space, tab, line feed, carriage return; three groups in order: name starts with, name contains, alias contains; each group sorted by lower-case name then id.
- B-12 inventory order: (days left, lower-case name, addedAt, id).
- B-05 amount text: g/ml below 10 to one decimal else whole (ties up); pieces and cloves to the nearest half; L to two decimals; scaling is exact rational arithmetic (`amount * servings / base`), never divide first.

**Vector file.** `rules-vectors.json` = `{schema:1, today:"2026-04-18", rules:{"B-nn":[{name,input,expected}]}}`; decimals are strings; one tolerance (B-22 `fill`, 0.000000001); fixture files `c1.json` (mini content: catalog, four recipes `tomato-pasta`, `chicken-stir-fry`, `vegetable-curry`, `lentil-soup`, one protein swap cluster), `kitchens.json` (K1, K2, K3, K5, K6, K7, K8 as store rows), `session-ss1.json`; row ids `00000000-0000-4000-8000-%012d`; `addedAt` = `2026-04-10T%02d:%02d:00Z` from minutes after 08:00. Content C2 (one recipe `lemon-pasta`, clusters `acid`, `milk`, `garlic`, factors lemon->vinegar 15 ml, lime->vinegar 10 ml, garlic cloves->garlic-powder 0.5 g) and C2 without factors are inline in some B-08/B-10/B-16 cases.

**Mutation tool `tools/vector_mutants.py`.** Loads the oracle source, applies one named mistake at a time (`Mutant(id, rule, swift_type, change, function, edits, const)`; an edit must match exactly once), rebuilds `vectors()` and requires at least one case to differ. Options `--list --rules --task T-xx --batches --batch N --self-test`. A mutant that makes the oracle refuse a long decimal is re-run with a lenient number writer so the list of failing cases is complete. 144 mistakes were defined, including: round half-even, divide before multiply (kill needs a tie such as `3.25 g` base 3 servings 3), exact vs shown amount, month without year, `d > 0` for used-in-time, a dropped addedAt or id tie-break, 7 or 15 day digest, expired row counts as use-first, rescued ingredients not de-duplicated, member without factor ends the search (`continue` vs `break`), title compared with capitals, optional line not counted as missing, Smart Swap before Almost Ready, presence row not the soonest, expired row in the presence line, `startingQuantity` follows quantity, swapped line listed in the share text, litre/piece stepper floor, label rounds down, one hour without its hour part, timer ending exactly now keeps the session. Swift use: after a Core task is green, apply one batch of mistakes in a throw-away commit; CI must fail every listed case; delete the branch.
